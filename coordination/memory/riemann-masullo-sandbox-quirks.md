Seen on 2026-11-21:
- elan is installed in `~/.elan` (PATH added to /etc/sandbox-persistent.sh). The domains `*.lean-lang.org` and `cache.mathlib.org` had to be allowlisted.
- A full `lake build` fails on the chapter index modules (each does `import Mathlib`) with "Too many open files" when they build in parallel on the repo mount. Building those modules one at a time with `lake build <Module>` and then re-running `lake build` works.
- The repo's host disk was nearly full: about 7 GB free after the Mathlib cache, and it dropped further from outside activity. Check `df` before large builds.
- Token (classic) has scopes repo, workflow, read:org since 2026-11-21 ([[github-token-scope]]). If a gh GraphQL command (`gh pr list`, `gh pr edit`) returns 401 instantly (~300 µs), it is gh's 24h response cache in ~/.cache/gh replaying an old 401: `rm -rf ~/.cache/gh`.
- `scripts/paper.sh` needs poppler-utils (`sudo apt-get install -y poppler-utils`); the overlay root is not persistent across sandbox recreation.
- The sandbox can crash (seen 2026-11-21 ~20:15Z). Afterwards: background services are dead, so restart them with `cd /home/agent/sweeptools && setsid nohup ./{warm,memguard,watchdog}.sh >> <name>.log 2>&1 < /dev/null &`. Cron jobs are gone: re-create the hourly check. Some subagents restart automatically from their transcripts, others do not; check ListAgents and the worktrees' .agent/STATE.md, and hand unfinished work to fresh agents. elan, poppler and the worktrees survived this crash.
- The warm base silently stopped advancing after the 2026-11-21 crash. From 19:58Z on, every warm.sh build failed with "failed to open file" on Mathlib .oleans: the index modules exhaust the HOST mount's file handles, and the process ulimit (1M) is not the cause. New worktrees then started ~6 h behind main, and every agent recompiled 38 changed upstream files after rebasing. Fixed 2026-11-21 ~23:10Z: warm.sh now rebuilds the failed modules one at a time and retries (old copy in warm.sh.bak). Watch warm.log for "build failed"; the hourly check should look at it.
- Lake artifact cache — DISABLED 2026-11-22 ~00:30Z: when Lake reuses a module from the cache it writes NO local .olean, which breaks scripts/signatures.sh and `lake env lean` (found by the #1219 prover; the workaround was copying cached files back by the hashes in each .trace). The exports are removed from /etc/sandbox-persistent.sh (it now `unset`s them) and commented out in warm.sh/build.sh. Untested fix: LAKE_RESTORE_ARTIFACTS=true. Test it in a tmp worktree before re-enabling. The cache dir is kept. - **Use `lake lean <file>`, never `lake env lean`** (AGENTS.md, 2026-11-22). Only `lake lean` applies lakefile.toml's leanOptions: maxSynthPendingDepth=3, autoImplicit=false, and linter.unusedSectionVars=false, a linter that took 20 min on one AppD proof. Our sweep.py ran `lake env lean --json` in res1-res4 and in the first sieve runs. That likely explains the whole-file timeouts and some of the "#1288 elaboration timeouts" hunters reported on Ch02/Ch04/AppD (their fail-fast probes used it too). Fixed 2026-11-22 ~04:50Z: sweep.py now runs `lake lean <rel> -- --json`, and HUNTER/CRITICAL_PROVER/SIEVER.md say `lake lean`. Re-test "blocked" labels before believing them. Also new: never print raw Exprs (`repr` used 70 GB).
